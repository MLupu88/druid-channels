3. FIX KPI DRILL-DOWN LOGIC
==================================================

THIS IS HIGH PRIORITY.

The current implementation uses prospect statistics for multiple unrelated KPI drill-downs.

Remove this behavior.

A KPI detail MUST use the SAME:

- metric definition
- period
- territory filter
- underlying records

as the KPI shown in the table.

Create ONE common KPI detail contract.

Suggested endpoint:

GET /api/kpis/details

Parameters:

metric
period
territory

Example:

GET /api/kpis/details?metric=partner_sourced_pipeline&period=2026-Q3&territory=global

Response example:

{
  "metric": "Partner-Sourced Pipeline",
  "current": 1420000,
  "target": 1600000,
  "previous": 1190000,
  "trend": "up",
  "data_status": "connected",
  "data_source": "HubSpot Deals",
  "last_updated": "2026-08-07T04:15:00Z",
  "what_changed": "+€230K since last week",
  "by_territory": [
    {
      "territory": "DACH",
      "value": 420000
    }
  ],
  "records": []
}

Do not reuse prospect stats for unrelated metrics.

==================================================
4. KPI RECONCILIATION RULE
==================================================

The drill-down MUST reconcile with the KPI clicked.

Example:

Overview:

Partner-Sourced Pipeline
€1,420,000

Then:

SUM(detail.by_territory.value)

must equal:

€1,420,000

and where records contain monetary contribution:

SUM(records.value)

must also reconcile unless the metric explicitly uses a different aggregation.

If values do not reconcile:

DO NOT silently show the result.

Show:

"Data does not reconcile"

and provide the mismatch amount internally/admin-side.

Add a reusable KPI reconciliation check.

This is important because the Head of Channels must be able to trust every number.
